### Найденные баги и фиксы

**Баг #1 — тупиковое состояние при пустом фильтре (пункт 6, "Размеченные")**

- Что сделано: сразу после загрузки (когда 0 записей размечено) выбран
  радио-пункт "Размеченные" в списке изображений.
- Ожидалось: список показывает предупреждение "Нет изображений по
  выбранному фильтру" и позволяет вернуться к "Все"/"Неразмеченные".
- Получено: приложение показывает предупреждение и рисует **отдельный,
  несвязанный** `st.radio(..., key="empy_filter")` в блоке
  `frontend/app.py` (ветка `if not filtered:`). Клик по любому пункту
  этого радио (включая "Все") **ничего не меняет** — `st.session_state
  .filter_option` в этой ветке никогда не читается и не обновляется, и
  реальный список изображений остаётся пустым/недоступным до
  перезапуска сессии Streamlit (например, обновления вкладки браузера).
  Воспроизведено дважды подряд (Playwright, отдельные скриншоты
  `BUG_stuck_01_marked_empty.png` → `BUG_stuck_03_after_clicking_unmarked.png`
  в scratchpad прогона), поведение стабильно.
- Локация: `frontend/app.py`, блок `if not filtered:` (строки ~92-102 в
  текущей версии) — радио с `key="empty_filter"` не подключён к
  реальному `st.session_state.filter_option`.
- Важно: как только появляется ≥1 запись, подходящая под фильтр
  "Размеченные"/"Неразмеченные", сам фильтр работает корректно (это
  подтверждено отдельно в пункте 6 после разметки одной записи) — баг
  проявляется только в пограничном случае "0 результатов".

**Баг #2 — `AnnotationManager.save_changes()` падает при плоской структуре файлов (пункты 12, 28)**

- Что сделано: (а) 10 раз подряд нажата "✓ Подтвердить" (автосохранение
  при накоплении 10 изменений); (б) отдельно нажата кнопка сайдбара
  "💾 Сохранить всё".
- Ожидалось: (а) счётчик "Несохранено" сбрасывается в 0, показывается
  "💾 Автосохранение"; (б) показывается "✓ Сохранено", `unsaved_changes`
  сбрасывается.
- Получено: (а) счётчик стабильно доходит до 10 и **не сбрасывается**
  (после 10 кликов подряд — "Несохранено: 10"), автосохранение
  проваливается **без единого сообщения об ошибке** (в этой ветке кода
  нет `else: st.error(...)`); (б) кнопка сайдбара явно показывает
  `Ошибка сохранения: [Errno 17] File exists:
  '/data/regression_test/crop_9f8f64de4c0f45d9a1aa38f0d321fd79.webp'`.
- Причина (см. `frontend/src/annotations.py`,
  `AnnotationManager._load_status_cache`/`save_changes`): путь кэша
  статусов строится как `base_dir / Path(first_rel_path).parts[0] /
  "status_cache.txt"`. Когда `rec.txt` использует **плоскую** структуру
  (изображения лежат прямо в рабочей директории, без подпапки —
  ровно наш тестовый `data/regression_test/`), `parts[0]` — это **имя
  файла первого изображения**, а не имя подпапки. `save_changes()`
  затем пытается `self.cache_path.parent.mkdir(parents=True,
  exist_ok=True)`, то есть создать директорию с именем, совпадающим с
  уже существующим файлом изображения → `NotADirectoryError`/`OSError
  [Errno 17]`. Всё исключение перехватывается общим `except Exception`,
  весь `save_changes()` возвращает `(False, ...)`, хотя `rec.txt` к
  этому моменту **уже был успешно перезаписан** (`write_text` вызывается
  раньше блока с кэшем) — то есть частичная, необъявленная запись на
  диск при формально проваленном сохранении.
- Важно: это не регрессия разбиения на `src/` — тот же код существовал
  бы и в монолите; баг вскрылся именно потому, что тестовый датасет
  (по заданию для этого прогона) использует плоскую структуру файлов
  без подпапки. Любой реальный рабочий каталог с таким же плоским
  расположением файлов будет затронут.
- Рекомендация для фикса (не выполнялся в рамках этого прогона): в
  `_load_status_cache`/`save_changes` использовать `base_dir` напрямую
  для `status_cache.txt`, когда у `relative_path` нет родительской
  директории (`Path(first_rel_path).parent == Path('.')`), либо явно
  проверять `is_dir()`/`exists()` перед `mkdir()`; также добавить
  `else: st.error(msg)` в автосохранение при `>=10` изменений, чтобы
  сбой не был молчаливым.
